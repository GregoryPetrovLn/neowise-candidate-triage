# Тестовое Neowise. AI-помощник для входящих заявок

Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту. Если модель не ответила вовремя или ответила некорректно, страница честно говорит «разберите вручную» и не показывает ничего из предыдущих попыток.

## Запуск

Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
# или
npm start
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`:

```sh
PORT=8080 node server.mjs
```

## Тесты

```sh
npm test
# эквивалентно
node --test
```

Тесты лежат в `test/triage.test.mjs` и используют встроенный `node:test`, внешних библиотек нет. Они поднимают сервер на свободном порту и проверяют:

- некорректный ввод (пустая строка, пробелы, нет поля, не строка, битый JSON) → `400 {"status":"invalid_input"}`;
- каждый сценарий сбоя имитатора (`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`) → `200 {"status":"manual_review","topic":null,"draft":null}`;
- что при `[timeout]` ответ приходит около 300 мс, а не через 1200 мс работы имитатора;
- успешные ответы для тем `delivery`, `pricing`, `other`;
- чистые функции валидации входа и ответа модели.

## Контракт `POST /api/triage`

Запрос: `{"text": "непустая строка"}`.

| Ситуация | HTTP | Тело |
|---|---|---|
| Пустой, отсутствующий, нестроковый `text` или битый JSON | 400 | `{"status":"invalid_input"}` |
| Модель ответила корректно | 200 | `{"status":"ready","topic":"delivery\|pricing\|other","draft":"…"}` |
| Таймаут 300 мс, ошибка модели, не-JSON, недопустимая тема, пустой черновик | 200 | `{"status":"manual_review","topic":null,"draft":null}` |
| Тело больше 64 КБ | 413 | `{"status":"payload_too_large"}` |

Причина каждого `manual_review` пишется в stderr сервера строкой `[triage] manual_review: …`. По этим строкам можно считать доли сбоев по типам.

## Как устроено

- `server.mjs` — HTTP-сервер. `createApp({ classify, timeoutMs })` собирает сервер с подменяемой моделью и лимитом ожидания, это используется в тестах. Запуск `node server.mjs` стартует сервер на порту из `PORT`.
- `mock-ai.mjs` — имитатор модели, не менялся. Принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
- `index.html` — страница менеджера. Перед каждым запросом очищает прошлый результат, блокирует кнопку на время ожидания, при `ready` показывает тему и черновик, при `manual_review` показывает предупреждение, при сетевой ошибке — отдельное сообщение. Пустой ввод не отправляется на сервер.
- `test/triage.test.mjs` — тесты.

## Польза для менеджера

Менеджер получает готовый черновик ответа за доли секунды вместо того, чтобы писать его с нуля, а при сбое модели не теряет время на разбор битого ответа. Измерять можно так: среднее время от открытия заявки до отправки ответа клиенту (до и после внедрения) и доля заявок со статусом `ready` против `manual_review` по логам сервера.
